## 修复：离线期间消息的单对号不实时变双对号（2026-08-02 晚）
- **场景**：A/B 聊天中 B 退出，A 发消息=单对号；B 重新上线回到对话后 A 的单对号不变（刷新也不稳）。
- **根因**：B 上线进入会话只调 HTTP GetConversation（后端 MarkAsRead 只改 DB，不推 WS）；前端只在收到新 WS private 消息时发 read_receipt，加载历史消息时从不发，A 收不到实时回执。
- **修复**：前端 chat.js 新增 `sendReadReceipts()`，在 `selectFriend` 加载历史后对"对方发来且未读（is_read=false）"的消息逐个补发 `{type:'read_receipt', msg_id, from_uid}`。后端 handleReadReceipt 已有按 msg_id 查库并推送发送方逻辑，无需改动。
- **教训**：进入会话加载历史后必须补发已读回执，不能只依赖实时消息触发。
- **部署**（2026-08-02 17:43）：仅前端，备份恢复 config.js 后 scp + nginx reload。发现新坑：scp 上传的目录权限为 700（`drwx------`），nginx 静态文件返回 403，需 `chmod -R 755 /root/workspace/im-toy/public` 修复。验证 /pages/chat.js 200 且含 sendReadReceipts。
- **commit c7572b6**：feat: 用户在线状态显示与已读回执补发（9 文件，+53/-7）。排除本地 public/config.js（仅换行符差异）与 .codebuddy/。

## 实时在线状态（presence 推送）—— 实现并部署
- **背景**：原在线状态是登录快照（无轮询无推送），好友上下线后列表绿点不更新。
- **后端 websocket.go**：新增 `notifyFriendsPresence(uid, online)`，通过 `infra_repo.NewFriendRepository().FindByUID` 查好友，逐个 `SendToUser` 推 `{type:"presence", uid, online}`。触发点：WS 连接建立（online=true）、cleanup 断开（false）、cleanupExpiredConn 心跳超时（false）。
- **坑**：`cleanup`/`cleanupExpiredConn` 持 `mu.Lock` 时不能调 `SendToUser`（其内部 `mu.RLock` 会死锁）——下线通知必须移到锁外，cleanupExpiredConn 用 expired 切片收集后锁外推送。
- **前端**：ws.js 加 presence 分发；friends.js 加 `updateFriendOnline(uid, online)`；chat.js 加 `case 'presence'`：更新侧栏绿/灰点（render）+ 当前会话对方实时更新 peerOnline/renderAll。
- **部署**（17:55）：后端改动需重新构建镜像。流程：备份 config.js → scp（后端源码+前端+nginx+config.prod.yaml+compose）→ 恢复 config.js + chmod 755 → 停基础服务+swap → `docker compose build backend` → 起 im-toy 服务 → **必须再 `cd /root/workspace && docker compose up -d mysql redis kafka`**（基础服务在独立 compose，构建前停掉后必须手动重启，否则 backend Restarting 循环）→ nginx reload。验证全部 200。
